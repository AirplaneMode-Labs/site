Sprint 5: an offline PDF answer, and what it costs in memory (draft)

Sprint 5 (planned 4 January 2027 to 17 January 2027, build work started early on 18 November 2026 by the owner's choice). Finished on 19 November 2026 from the saved evidence and the Sprint 5 report, and from nothing else. This page is a draft for owner approval: it is not listed and asks search engines not to index it.

Rules this page follows: every figure sits next to the file it was read from, and a build test recomputes it from that file. The Sprint 5 done-when is quoted only as: build done on Apple M5 Pro 48 GB; 8 GB Windows done-when NOT met (owner runbook step 5). Anything about the 8 GB laptop is not measured on 8 GB.

What we tried

  • One offline path in a browser tab: triage a PDF with pagetriage, read its text layer with pdf.js in a worker of its own, gate Devanagari text with glyphsift, keep chunks and vectors in localdata, and answer with a small local model (Qwen3-0.6B) that names its source pages (evidence/sprint-5/ARCH/fresh-deps/logs/e2e.log).
  • A signed model bundle that the page verifies before it loads anything, downloaded once and then read from the device, with the network blocked afterwards (evidence/sprint-5/ARCH/fresh-deps/logs/bench-e2e.log).
  • Stop that really stops: the engine is ended on Stop and loaded again for the next question (evidence/sprint-5/ARCH/fresh-deps/logs/e2e.log).

What held up

  • The answer to the grace-period question was right and cited the right page in 6 of 6 runs, five in one session and one after a full Chrome restart, with 0 requests after the network was blocked in every run (evidence/sprint-5/ARCH/fresh-deps/logs/bench-e2e.log).
  • The browser end-to-end suite passed: 23 passed, and the Devanagari gate test passed: 2 passed (evidence/sprint-5/ARCH/fresh-deps/logs/e2e.log and evidence/sprint-5/ARCH/fresh-deps/logs/gate.log). The unit suite passed: 515 tests (evidence/sprint-5/ARCH/fresh-deps/logs/final-dockit-ci.log).
  • The built page measured 821,731,328 bytes by the du figure that the size guard of pages.yml reads, against a guard of 1,000,000,000 bytes (evidence/sprint-5/ARCH/fresh-deps/logs/size.txt).

What did not

  • The fixed question set scored 24 of 36 answerable rows right with the right source page over the 6 runs, and 4 of 6 on the first run. The same two questions were wrong in every run (evidence/sprint-5/ARCH/fresh-deps/logs/bench-e2e.log).
  • Memory is the open risk. The Chrome process tree peaked at a median of 6,283 MiB and at worst 6,377 MiB (about 6.2 GiB) during one question. Whether that fits an 8 GB laptop is not measured on 8 GB (evidence/sprint-5/ARCH/fresh-deps/logs/bench-e2e.log).
  • Four repositories went red in CI after the first push on 18 November 2026, and the fixes were pushed the same day (SPRINT-5-REPORT.md).

Numbers (Apple M5 Pro; not measured on 8 GB)

  • Time to first token for the first question: median 7,731 ms, worst 7,861 ms. Total: median 9,280 ms, worst 9,435 ms. Command npm run bench:e2e in dockit, machine Apple M5 Pro 48 GB, 5 runs in one session (evidence/sprint-5/ARCH/fresh-deps/logs/bench-e2e.log).
  • Peak memory of the Chrome process tree: median 6,283 MiB, worst 6,377 MiB (evidence/sprint-5/ARCH/fresh-deps/logs/bench-e2e.log).

Limitations

  • The 8 GB Windows laptop is not measured on 8 GB: every figure above is from one Apple M5 Pro 48 GB machine, and nothing has run on Windows.
  • Text-layer PDFs only: a scanned PDF is refused, and OCR is not yet supported. The answer model is a small demo model and can be wrong, so the source pages are shown.
  • The engine runs on one thread, because GitHub Pages cannot send the headers a faster path needs, so an answer takes seconds.
